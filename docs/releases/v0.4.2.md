# v0.4.2 — 自动同步默认不推送，体检与备份检查收紧，文档和脚本实际行为对齐

本版本以安全和准确为主：自动同步不再自动推上公开仓库、不再清掉工作区里没提交的东西；统一体检遇到看不清的情况改记 `unknown`，不再判成通过；备份前的明文密钥检查覆盖面加宽；几份文档按脚本实际行为改写。**这一版没有改任何 `.ps1` 脚本**，已确认的 Windows 脚本问题列在已知问题里，下一个版本在 Windows 真机上验证后再改。

## 变更要点

- **自动同步默认不推送**：`tools/auto_update.py` 默认只在本机提交，要推送必须加 `--push`；工作区不干净时拒绝运行；源目录里的新文件要用 `--allow-new` 点名；仓库里人工改过的文件不会再被源目录覆盖（`--source-wins` 才放行）；失败时只还原这次同步动过的文件，不再执行 `git reset --hard` 和 `git clean`；隐私闸门加固。
- **统一体检少报“通过”**：macOS 的接口作用域默认路由、隧道与非隧道混合的 IPv6 默认路由、读不到的 IPv6 路由表、只有部分网卡满足的 Windows DNS、读不了的 MCP 或 CLI 配置、进不去的本地数据目录，现在都记 `unknown`；本地 MCP 计数补上按项目存放的条目和项目 `.mcp.json`（`--project-dir`）；在 macOS 和 Linux 上输出文件只有自己能读写（Windows 上沿用所在文件夹的权限）；`--from-json` 遇到坏文件报一行错。
- **备份前的明文密钥检查加宽**：`claude_local_data.py` 检查参数列表、`env` 和 `headers` 下的常见密钥名、URL 里的口令、命令行参数；不是严格 JSON 的配置按“无法确认”拒绝；`--allow-inline-secrets` 会列出放过了什么；按文件名排除的条目数写进清单。
- **路由与移动端**：Android 校验器遇到以前会打出 traceback 的字段类型错误时改报一行错（检查没有加严），通过时照实说只查了结构；名单拉取拒绝和保留网段重叠的前缀；`mobile/README.md` 逐条列出 13 条规则并写清导入前的备份办法。
- **文档和离线网页对齐实际行为**：`.wfw` 备份只属于 LAN DNS Guard；断网开关更新范围要先 `Remove` 再 `Install`；执行策略、手工撤销、断线演练和已知问题写进 [WINDOWS-KILL-SWITCH.md](https://github.com/rumpelpalmour757-lgtm/cross-platform-privacy-environment-kit/blob/v0.4.2/WINDOWS-KILL-SWITCH.md)；离线网页的断网规划器改用脚本的真实规则表，生成的命令和文档一致，卸载命令单独复制。
- **补记 `db8187e`**：v0.4.1 标签之后的那次体检修复（Unix 接口类型字段、采集器不可用时记 `unknown`、子进程不继承终端输入）当时没有发布，这一版一并带上。

完整清单见 [CHANGELOG.md](https://github.com/rumpelpalmour757-lgtm/cross-platform-privacy-environment-kit/blob/v0.4.2/CHANGELOG.md)。

## 升级要注意

### 用自动同步（`tools/auto_update.py`）的人

**自动同步的行为变了**，升级前请读一遍 [AUTO-UPDATE.md](https://github.com/rumpelpalmour757-lgtm/cross-platform-privacy-environment-kit/blob/v0.4.2/AUTO-UPDATE.md)：

1. **默认不再推送。** 以前全部成功后会自动 `git push`；现在提交只留在本机，要推送得加 `--push`（只推 `main` 或 origin 默认分支，提交邮箱不是 noreply 地址时不推）。原来靠定时任务每周自动推送的，要自己在任务的命令行里加上 `--push`；不加就只同步、不推送。
2. **工作区不干净会拒绝。** 仓库里有没提交的改动或未跟踪的文件时，脚本列出它们后退出（退出码 2），什么都不动。
3. **人工改过的文件不再被源目录悄悄覆盖。** 仓库里最后一次提交不是 `auto-update:` 开头的文件，要被源目录的版本覆盖或删除时，整次运行停下并列出；确认源目录的版本更新时加 `--source-wins`。
4. **新文件要点名。** 源目录里出现仓库没跟踪过的文件时停下，要进仓库的用 `--allow-new 路径` 逐个点名。
5. **先处理跑定时任务的那份本机克隆。** 合并这一版以后，先在那份克隆里 `git pull`，或者先停掉定时任务；否则旧脚本照旧会执行 `git reset --hard`、`git clean` 并自动推送。
6. **Windows 上的定时任务按新写法重建。** 原来的写法（程序 `py`、参数 `-3 tools\auto_update.py …`）不留日志，这一版新增的拒绝原因（新文件、人工改动）只打印在一闪而过的窗口里。请按 [AUTO-UPDATE.md](https://github.com/rumpelpalmour757-lgtm/cross-platform-privacy-environment-kit/blob/v0.4.2/AUTO-UPDATE.md) 的“定时任务怎样配”改成经 `cmd.exe` 写日志的那一行，退出码 2 时去日志里找 `REFUSED:`。
7. **升级前把这一版改过的文件拷回本机源目录。** 下面左列的文件在源目录维护，这一版直接在仓库里改了它们；不拷回去的话，新脚本会把它们列为人工改动并停下（旧脚本则会用源目录的旧版本把它们冲回去）。全部拷回以后同步照常进行。仓库里现在还没有一次自动同步提交，所以以后源目录里每个文件第一次再改时（不只是左列这些），同步都会停一次：先把列出的文件和仓库里的版本 diff 一遍，确认源目录的版本是新的，再加一次 `--source-wins`，那次自动提交以后这些文件就恢复正常。右列的文件只在仓库里维护，同步不读源目录里的同名文件，不用拷。

### 其他行为变化

- **体检单**：上面列的几种情况从“通过”或“缺口”改成了 `unknown`，三态摘要里 `unknown` 会比以前多。这是如实反映“没看清”，不是新出了问题。体检单的范围说明现在写明包含宿主机时区、UTC 偏移和区域语言。
- **备份**：选中范围里不是严格 JSON 的 `settings.json`、`settings.local.json`、`.mcp.json`（带注释、尾逗号）以前会静默放行，现在默认拒绝；改成严格 JSON，或者确认后加 `--allow-inline-secrets`。明文密钥检查比以前查得宽，hook 或 statusLine 命令里出现“名字=一个词”“名字: 一个词”（如 `API_TOKEN=abc`、`echo 'Password: abc'`）时可能被拒；报错会列出文件和键路径，确认不是密钥后加 `--allow-inline-secrets`。对环境变量的引用（`$env:变量`、`%变量%`、`${变量}`）、grep 的匹配模式、几个词的提示文字不算密钥。
- **Windows 脚本**：`.ps1` 没改。断网开关和 LAN DNS Guard 目前请放在个人主目录下的子文件夹运行，放在 `C:\Program Files` 下会被拒；脚本跑不起来时的手工撤销命令见 `WINDOWS-KILL-SWITCH.md`。

## 已知问题

这一版没有改 `.ps1`，下面几条照旧存在，下一个版本修，修改要在 Windows 真机上验证：

- 两个管理脚本的目录权限检查掩码算错，工具包放在 `C:\Program Files` 下时 `Install`、`Remove` 都被拒。
- 断网开关 `Remove` 可能输出 `removed` 而同组里还留着规则。
- LAN DNS Guard 的 `Install` 中途失败时不恢复原有规则；同组里有对不上的规则时整体拒绝卸载。
- `Test-ProxyState.ps1` 默认把 IPv4 和 IPv6 混在一起预检，TUN 只接管 IPv4 时请加 `-AddressFamily ipv4`。
- 虚拟网卡选不进断网开关的保护范围，建了外部虚拟交换机以后是否仍然覆盖没有实测。

每一条的确认办法和手工处理办法见 `WINDOWS-KILL-SWITCH.md` 末尾的「已知问题」；其余较小的问题列在 `CHANGELOG.md` 里。

## 没有验证的

- PowerShell 脚本只在 CI 的 windows-latest（英文系统）上做过语法解析，并运行了两个管理脚本的 `Preview`；`Install`、`Remove`、`Status` 没有在 Windows 上运行过，离线网页生成的命令也没有在 PowerShell 里执行过。
- 没有 Mac 真机，macOS 的路由判定只用合成的 `netstat` 输出测过。
- 没有联网核对域名和网段清单现在是否仍然准确。
- 自动同步的新保护只在临时仓库里测过，没有在作者的机器和定时任务上跑过，也没有真推到 GitHub。
- 全套测试由 GitHub Actions 在 ubuntu-latest 的 Python 3.10、3.13 和 windows-latest 的 Python 3.13 上跑，本地另在 Linux 上用 Python 3.11、3.12、3.13 跑过；没有在中文（繁体或简体）Windows 上跑过，Windows 的代码页、长路径、目录联接、文件名大小写这几类情况是用模拟测的。
- 离线网页没有在真实浏览器里打开过。
